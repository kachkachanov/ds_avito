# Классификация ботов по событиям Авито

Тестовое задание: нужно для каждой `cookie_id` сказать, насколько вероятно, что это бот — автоматизированный сбор данных. Метрика — Precision при Recall ≥ 0.70.

**На скрытом тесте получилось P@R≥0.70 = 0.792.** Константный ответ даёт 0.094, так что сигнал есть.

## Как запустить

Нужен Python 3.12.7, зависимости в `requirements.txt` (pandas 2.3.3, numpy 2.3.3, scikit-learn 1.8.0). Все сиды зафиксированы (`SEED = 42`, у бустинга сиды 0–4). Никаких API и LLM, только sklearn.

```bash
pip install -r requirements.txt
python3 solution_final.py        # или прогнать solution.ipynb сверху вниз
```

Рядом должны лежать `data/`, `metric.py` и `sample_submission.csv`. На выходе — `submission.csv` и `results.csv` (сравнение вариантов).

## Что внутри

**Данные.** Убираю точные дубли, сортирую события по `(cookie_id, event_ts)` и оставляю только те, что попали в окно куки `[window_start_ts, window_end_ts)`. Куки без событий не выкидываю — просто признаки NaN и `n_events = 0`.

**Признаки.** Разбиты по группам, чтобы можно было нормально делать ablation:

| Группа | О чём |
|---|---|
| `volume` | сколько событий и объявлений (baseline из quickstart) |
| `timing`, `timing2` | интервалы между событиями, регулярность, burstiness, автокорреляция, «машинные» таймстемпы (ровные секунды), время до первого события |
| `sess` | сессии по паузе > 30 минут |
| `diversity` | разнообразие объявлений, категорий, локаций, запросов, глубина выдачи |
| `mix`, `seq` | доли типов событий, частые переходы, листание страниц |
| `pointer`, `pointer2` | пропуски и вариативность курсора, отдельно по платформам, длина шагов |
| `ua` | структурные признаки UA (библиотеки, headless, версия Chrome), не сырая строка |
| `cross` | насколько UA, объявления, запросы и секунды «общие» с другими куками того же дня |
| `age` | возраст куки на начало окна |

**Модель.** `HistGradientBoostingClassifier` с сильной регуляризацией — данных мало, ботов в train ~740. Усредняю по сидам, в бленде с `ExtraTreesClassifier` по рангам.

## Валидация

Тестовые окна идут позже train по времени, так что валидация тоже временная, не случайная. Два сплита: окна с 17 апреля (A) и с 14 апреля (B). Метрика — официальная из `metric.py` (одинаковые score идут одной группой). Ботов в valid ~160, поэтому P@R шумит, и вариант выбираю по среднему PR-AUC на двух сплитах.

## Что пробовал

| Шаг | Валидация (сплит A) | Скрытый тест |
|---|---|---|
| Baseline: только `volume` (2 признака) | P@R 0.117, PR-AUC 0.191, ROC-AUC 0.656 | — |
| + timing, diversity, mix, pointer, ua, age (v2) | P@R 0.709, PR-AUC 0.759, ROC-AUC 0.929 | 0.727 |
| + timing2, pointer2, seq, регуляризация, бленд (v3) | см. `results.csv` | 0.770 |
| + cross, sess (финал) | см. `results.csv` | **0.792** |

Ablation для v2 (сплит A, P@R без группы): без `timing` — 0.507, без `pointer` — 0.596, без `diversity` — 0.651, без `mix` — 0.673. А вот `volume`, `ua` и `age` можно выкинуть без изменений вне шума (~0.72–0.74). Основной сигнал — временная регулярность и поведение курсора. Полная таблица финального запуска в `results.csv`.

## Честные ограничения

- В valid ~160 ботов, один бот двигает recall на ~0.6%. Различия P@R меньше ~0.03 — это шум.
- Группа `cross` считает статистику по всем кукам суточных окон, включая test (но без `target`). В продакшене её надо считать по скользящему окну.
- Гиперпараметры почти не подбирал - только регуляризацию, из-за малого числа ботов.
- Тест позже train, так что признаки, завязанные на версии браузера и возраст куки, могут дрейфовать.
- Из библиотек только pandas, numpy, scikit-learn.
